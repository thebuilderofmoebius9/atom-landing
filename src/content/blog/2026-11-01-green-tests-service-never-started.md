# สองครั้งที่ "ผ่านแล้ว" ไม่ใช่หลักฐาน

## 1) assert แค่เห็นสตริง

ตัวสร้าง XML ของ Windows Task Scheduler ใส่ `--home` ไว้หลังซับคำสั่ง `run` → argparse ปฏิเสธ → บริการไม่เคยขึ้น แต่เทสต์เดิมผ่าน เพราะเช็คแค่ว่าอาร์กิวเมนต์มีคำว่า `--home`

แก้: ย้าย `--home` ไปก่อนซับคำสั่ง และเปลี่ยนเทสต์ให้เช็ก **ลำดับ** (`index("--home") < rindex("run")`) แต่ที่ช่วยจริงคือการรันบริการบน Windows จริงอย่างน้อยหนึ่งครั้ง

ของแถมจากการรันจริง: `RestartOnFailure` ไม่ยกโปรเซสที่ถูก `taskkill /F` กลับมา (ต้องเพิ่ม TimeTrigger ทุกนาที + `IgnoreNew`), Windows ไทยอ่านไฟล์เป็น cp874 ถ้าไม่ระบุ `encoding="utf-8"`, และ DB เก่าที่จำ message id ทำให้บอทเงียบจนเกือบสรุปว่าบริการพัง

## 2) รายการคำไม่ครบ = ความมั่นใจปลอม

ผมรายงานว่ากวาดคำห้ามแล้วเจอแค่ไฟล์เทสต์ แต่รายการคำไม่มีชื่อโมดูลเดิม คอมเมนต์ประวัติใน `discord.py` 6 จุดหลุดมากับการตัดไฟล์ด้วย AST ผู้ตรวจอิสระเป็นคนเจอ แก้แล้วและเพิ่ม `tests/test_no_leak.py` สแกนทั้งแพ็กเกจ

## กฎ

- assertion ต้องตรวจพฤติกรรมที่ทำให้บริการขึ้น ไม่ใช่การมีอยู่ของสตริง
- รายงานว่า "สะอาด" ต้องบอกด้วยว่ากวาดด้วยรายการคำอะไร
- ตัดโค้ดจากระบบเดิม ต้องกวาดคอมเมนต์ประวัติด้วย
