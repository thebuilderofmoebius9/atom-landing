# Watcher เงียบ 11 วันไม่ใช่เพราะไม่มีอะไรจะค้าน

## อาการ

Tenth Man Watcher — ระบบค้านอัตโนมัติที่คอยจับ blind spot / over-agreement — เงียบสนิทมา 11 วัน
(27 ส.ค. – 7 ก.ย. 2026) ไม่ใช่เพราะไม่มีอะไรให้ค้านจริง ๆ แต่เพราะทุกรอบตกไปที่ verdict
`no_finding` เหมือนกันหมด **ราว 1,400 ครั้งติด** โดยไม่มี error โผล่ให้เห็นที่ไหนเลย

## สาเหตุ

โมเดลที่ใช้ (`nvidia/nemotron-3-super-120b-a12b`) เปลี่ยนพฤติกรรมกลายเป็น reasoning model —
เทความคิด (chain-of-thought) ลงไปใน `message.content` ตรง ๆ ก่อนตอบ JSON จริง พอความคิดยาวจนชน
`max_tokens=400` (`finish_reason=length`) JSON เอาต์พุตเลยไม่เคยถูกปิดวงเล็บ `json.loads` พัง
ทุกครั้ง โค้ดจับ exception แล้ว fallback เป็น `parsed={}` → `finding=''` ซึ่งตกไปอยู่ verdict
เดียวกับ "ไม่มีอะไรจะค้าน" พอดี ระบบเลยมองไม่ออกว่ากำลังพังอยู่ เพราะหน้าตาเหมือนทำงานปกติทุกรอบ

## ทำไมเคสนี้อันตรายเป็นพิเศษ

"โมเดลเลือกจะเงียบ (ไม่มีอะไรน่าค้าน)" กับ "parse ไม่ผ่าน (โมเดลพังกลางทาง)" ทั้งสองอย่างจบที่
verdict เดียวกัน — `no_finding` ไม่มี log ไหนแยกสองเคสนี้ออกจากกัน 1,400 ครั้งที่พังจริง ๆ จึงไม่ต่าง
อะไรจาก 1,400 ครั้งที่ไม่มีอะไรจะพูด ระบบดูเหมือน "เงียบเพราะดี" ทั้งที่จริง ๆ "เงียบเพราะพัง"

## ทางแก้

- `chat_template_kwargs={"thinking": false}` ปิด reasoning mode ไม่ให้เทความคิดลง content
- ขยับ `max_tokens` จาก 400 → 800 กันชนเพดานซ้ำ
- เพิ่ม fallback regex คว้าก้อน JSON สุดท้ายจาก content เผื่อโมเดลยังพูดพล่ามอยู่บ้าง
- ผลลัพธ์: เวลาต่อรอบลดจาก ~14.5 วิ เหลือ 1-2 วิ และมีโพสต์ค้านจริงโผล่มา 2 ดอกใน 2 นาทีแรก
  หลังรีสตาร์ต

## กฎที่ถอดได้ ใช้ซ้ำได้กว้างกว่าเคสนี้

**1. "parse ไม่ผ่าน" ต้องมี `drop_reason` เป็นของตัวเอง แยกจาก "โมเดลตัดสินใจไม่พูด"**
อย่ารวม exception path กับ empty-result path ไว้ใน verdict เดียวกัน ไม่งั้นความเงียบจะดูเหมือน
ความสำเร็จ

**2. เปลี่ยน provider/โมเดลใต้ endpoint เดิม ต้องเช็ค `finish_reason` ทุกครั้ง ไม่ใช่แค่ status code**
`length` แปลว่าเอาต์พุตถูกตัดกลางคัน ไม่ใช่ "ตอบจบแล้วสั้น ๆ"

**3. reasoning model ไม่การันตีว่า JSON mode จะได้ JSON ล้วน ๆ**
ถ้าไม่ปิด thinking หรือไม่กันชน token ให้พอ ต้องมี fallback ที่แกะ JSON จากข้อความปนได้
ไม่ใช่พึ่ง `json.loads` ตรง ๆ อย่างเดียว
