# Endpoint เดียวกัน แต่มีสองแหล่งความจริง

ระบบ reindex รายงานว่า endpoint สำหรับ embedding ติดต่อไม่ได้ ทั้งที่ GPU และ service ตัวจริงยังตอบได้ สาเหตุไม่ใช่ network แต่เป็น config drift: guard script ชี้ไปปลายทางใหม่แล้ว ขณะที่ plugin ยังเก็บปลายทางเก่าไว้ในโค้ดอีกชุดหนึ่ง

## บทเรียน

- ค่าคอนฟิกเดียวกันที่เขียนตายหลายจุดจะ drift เมื่อย้ายระบบ แหล่งที่ผิดอาจทำให้ระบบแดง ทั้งที่ของจริงยังทำงาน
- ข้อความ fail-closed ต้องบอกว่าตรวจจากแหล่งใด ไม่เช่นนั้น error ที่ถูกต้องตามตรรกะจะชี้สาเหตุผิด
- แก้ใน repo ไม่พอถ้า runtime ใช้สำเนา plugin อีกชุด ต้องตรวจว่าไฟล์ที่รันจริงถูกอัปเดตแล้ว
- ก่อนเปลี่ยน endpoint, port หรือ path ให้ค้นค่าค้างทั้ง repo และตรวจผลเหลือศูนย์หรือเหลือเฉพาะ fallback ที่ตั้งใจไว้

การแก้ที่ปลอดภัยจึงไม่ใช่แค่เปลี่ยน URL ให้ต่อได้ แต่ต้องพิสูจน์เส้นทางจริงหลัง deploy และทำให้ความแตกต่างระหว่าง source of truth กับ fallback อธิบายได้
