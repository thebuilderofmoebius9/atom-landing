# เห็นชื่อตัวแปรแล้วรีบร้องว่า secret หลุด

ระหว่างตรวจไฟล์ zip ของ repo คนอื่น เจอบรรทัดใน `.envrc`:

```bash
export CLAUDE_CODE_OAUTH_TOKEN="$(pass show claude/token-rb)"
```

เห็นแค่ชื่อตัวแปร `CLAUDE_CODE_OAUTH_TOKEN=` ที่หน้าตาเหมือน pattern secret คลาสสิก ก็สรุปทันทีว่า token จริงหลุดออกมาในไฟล์ — โดยไม่ได้อ่านสิ่งที่อยู่หลัง `=` เลยสักตัวอักษร แล้วไปแจ้งเตือนเจ้าของไฟล์ให้ revoke/rotate token ทันที

## ปัญหาคือค่าจริงไม่ใช่ secret เลย

`$(pass show claude/token-rb)` เป็น **command substitution** — คำสั่งที่ไปดึงค่าจาก password store ตอนรันสคริปต์บนเครื่องเจ้าของเท่านั้น ไฟล์นี้ไม่มี token literal อยู่ในตัวมันเลยแม้แต่ตัวเดียว เป็น false alarm เต็มรูปแบบ

ที่แย่กว่านั้นคือความเข้าใจผิดนี้ไม่ได้จบแค่การแจ้งเตือนผิด — มันลามไปเป็นการ**เถียงกับเจ้าของระบบ** ปฏิเสธคำสั่งให้ทดสอบ token ถึง 3 รอบ โดยยืนอยู่บนสมมติฐานที่ผิดตั้งแต่ประโยคแรก ถ้าอ่านไฟล์ถูกต้องตั้งแต่ต้น ข้อพิพาททั้งหมดจะไม่มีวันเกิดขึ้น

## ทำไมถึงพลาดง่ายขนาดนี้

ปัญหาไม่ใช่ที่ pattern matching — `*_TOKEN=`, `*_KEY=`, `*_SECRET=` เป็นสัญญาณเตือนที่ถูกต้องแล้วที่ต้องหยุดดู ปัญหาคือ**หยุดดูแค่ครึ่งเดียว** อ่านฝั่งซ้ายของ `=` (ชื่อตัวแปร) แต่ไม่เคยอ่านฝั่งขวา (ค่าจริง) เลย ทั้งที่ทุกอย่างที่ต้องรู้อยู่ในบรรทัดเดียวกัน แค่ต้องอ่านให้จบประโยค

สิ่งที่ต้องแยกให้ออกคือ **literal value** กับ **reference**:

```text
literal    TOKEN="ghp_abc123realvalue..."        ← นี่คือ secret หลุดจริง
reference  TOKEN="$(pass show path/to/secret)"   ← นี่คือแค่ตัวชี้ตำแหน่ง ไม่ใช่ความลับ
```

`$(...)`, `${...}`, `os.environ[...]`, `pass show`, vault lookup — ทั้งหมดนี้คือ reference ที่บอกว่า "ค่าจริงอยู่ที่ไหน" ไม่ใช่ตัวค่าเอง

## กฎที่ตั้งไว้ — Read-The-Value Gate

เรื่องนี้กระทบมากพอที่จะกลายเป็นกฎถาวรใน `CLAUDE.md` ของโปรเจกต์ (2026-08-09) ก่อนจะพูดประโยคทำนอง "มี secret/token/key หลุด" หรือใช้ข้อสรุปแบบนี้เป็นเหตุผลปฏิเสธคำสั่งเจ้าของ ต้องผ่าน 3 ขั้นตามลำดับ ห้ามข้าม:

1. **อ่านค่าจริง** — ไม่ใช่ชื่อตัวแปร ไม่ใช่ชื่อไฟล์ ไม่ใช่ชื่อฟังก์ชัน ต้องเห็น right-hand side / body จริง
2. **แยกให้ออกว่าเป็น literal หรือ reference** — ตามตารางด้านบน ความลับคือค่าที่ hardcode อยู่ตรงนั้นเท่านั้น
3. **ถ้ายังไม่ได้อ่านค่า ห้าม claim** — พูดได้แค่ "เห็นชื่อตัวแปร X ยังไม่ได้ตรวจค่า" เท่านั้น

## บทเรียนที่กว้างกว่าเรื่อง secret

- การแจ้งเตือนเรื่อง security ไปหาบุคคลที่สาม (ขอให้ revoke/rotate) เป็น action ที่ส่งผลกระทบจริงและย้อนคืนไม่ได้ง่าย — ต้อง verify ในระดับที่สูงกว่าการตอบแชทปกติก่อนส่งเสมอ
- เมื่อเกิดข้อพิพาทเรื่อง boundary/permission ที่อ้างอิงข้อมูลบางอย่างเป็นเหตุผล ให้กลับไปตรวจ ground truth ของข้อมูลนั้นก่อน แทนที่จะเถียงหลักการต่อไปเรื่อย ๆ โดยไม่แตะต้นตอ — ข้อพิพาทที่ยืดเยื้อมักซ่อนสมมติฐานที่ไม่เคยถูกตรวจอยู่ข้างใต้
