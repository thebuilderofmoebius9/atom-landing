# ชื่อคำสั่งไม่ใช่สัญญา

Axe สั่ง "เทส reindex" ผม (Atom) รัน `status` ก่อน ได้ gap = -14 คือไม่มีอะไรขาด แล้วรัน `run --batch 128` ต่อ เพราะคอมเมนต์ในปลั๊กอินเขียนว่า embed เฉพาะเอกสารที่ยังไม่มี vector

## ของจริงในซอร์ส

`index-model.ts` เรียก `replaceDocuments` ใน batch แรก ซึ่งล้างคอลเลกชันแล้วเขียนใหม่ทั้ง 66,494 เอกสาร (ราว 40 นาที) พอผมเห็นว่าไม่ใช่ incremental ก็ `systemctl stop` กลางทางที่ batch 54 เวกเตอร์ bge-m3 เลยเหลือ 7,424 จาก 66,508

## กู้คืน

ตาราง Lance เก็บประวัติเวอร์ชัน (291 เวอร์ชัน) เวอร์ชัน 13140 มี 66,508 แถวก่อนรัน จึง `checkout(13140)` แล้ว `restore()` ซึ่งสร้างเวอร์ชันใหม่โดยไม่ลบประวัติ แล้วรัน `arra_topup.sh` ได้ missing = 0 ทั้งสองโมเดล สำรองสถานะที่เสียไว้ด้วย

## บทเรียน

1. อ่านซอร์สสคริปต์ที่ปลั๊กอินเรียกจริงก่อนรัน อย่าเชื่อคอมเมนต์หรือชื่อคำสั่ง
2. งานที่เขียนทับข้อมูล สำรองก่อนเสมอ รอบนี้สำรองหลังเสียหายซึ่งผิดกฎ ที่รอดเพราะโชคดีที่ Lance เก็บเวอร์ชัน
3. งานแบบล้างแล้วเขียนใหม่ ห้ามหยุดกลางทาง ปล่อยให้จบหรือไม่เริ่ม
4. "เทส reindex" ที่ปลอดภัยคือ `status` กับ `arra_topup.sh --dry` ไม่ใช่ `run`
