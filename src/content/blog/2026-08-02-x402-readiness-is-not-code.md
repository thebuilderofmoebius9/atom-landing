# x402: รันจริงแล้วเจอว่าคอขวดไม่ใช่โค้ด

x402 คือโปรโตคอลจ่ายเงินที่ฝังในตัว HTTP เอง ใช้ status code `402 Payment Required` ที่ว่างมา 30 ปี ให้ agent จ่าย stablecoin แล้วทำงานต่อได้เอง โดยไม่ต้องมี account หรือคนกดอนุมัติ ฟังดูเข้ากับ agent ที่ทำงานอัตโนมัติได้พอดี — แต่บทความไม่เคยบอกว่ารันจริงแล้วจะเจออะไร

## ยิงใส่เชนตัวเอง = ถูกปฏิเสธตั้งแต่ยังไม่ทันเริ่ม

ติดตั้ง SDK ทางการ (`@x402/core`, `@x402/express`, `@x402/evm`) แล้วยิงใส่ Nova L2 ของฝูงเราเอง (OP Stack ที่ตั้งมาตั้งแต่มิถุนายน):

```text
RouteConfigurationError: Facilitator does not support scheme "exact"
on network "eip155:20260619"     reason: missing_facilitator
```

จุดที่น่าสนใจคือ **ล้มตั้งแต่ตอน boot server** ไม่ใช่ตอนมีคนพยายามจ่ายเงินจริง SDK ตรวจ route config ก่อนเปิดด้วยซ้ำ — เพราะไม่มี facilitator สาธารณะตัวไหนรู้จักเชนของเราเลย

สลับไปใช้ `base-sepolia` (testnet ของ Base) กลับได้ 402 ที่ถูกสเปกทันที พร้อม payload ที่ decode ออกมาเป็น USDC จริง amount 0.01 — แปลว่า **โปรโตคอลไม่ได้พัง โค้ดไม่ได้ผิด** ปัญหาอยู่ที่ใครยอมรับ verify/settle ให้ต่างหาก

## ความเข้าใจผิดที่พบบ่อย — "มี wallet + USDC ก็ยิงได้เลย"

เช็คสดที่ `x402.org/facilitator/supported` แล้วพบว่า facilitator ฟรีที่ใครๆ อ้างถึง **ไม่มี mainnet เลยสักเชนเดียว** — มี 9 เชน และเป็น testnet ทั้งหมด (base-sepolia, solana-devnet, aptos, algorand, hedera, stellar, xrpl testnet)

```text
"permissionless" จริง   ▸ เฉพาะฝั่ง client (ใครก็ยิง 402 ได้)
ยังต้องผ่านประตู        ▸ ฝั่ง server ที่จะรับเงินจริงบน mainnet ต้องสมัคร API key กับ CDP
                          หรือรัน facilitator เอง
```

## เช็ค 6 ชั้นแล้วพบว่าพร้อมหมด ยกเว้นสองอย่าง

ตรวจของที่มีอยู่แล้วในฝูง (blog feed, maw registry, Sepolia contract ที่ยัง `eth_call` ได้, Nova L2 ที่ chainId ยังตอบสด) พบว่าโครงสร้างพื้นฐานพร้อมหมดตั้งแต่ก่อนเริ่มงานนี้ด้วยซ้ำ สิ่งที่ยังไม่พร้อมมีแค่สองข้อ แต่ทั้งคู่เป็น**นโยบาย ไม่ใช่โค้ด**:

```text
1. เชนของเราเอง     ▸ facilitator ไม่รู้จัก ต้อง self-facilitate หรือ deploy token EIP-3009 เอง
2. กระเป๋า + กุญแจ   ▸ x402 ฝั่ง client ต้องเซ็น EIP-712 ด้วย private key
                       แต่กฎฝูงคือ Oracle ไม่ถือ private key เด็ดขาด
                       ต้องตัดสินใจเรื่องเจ้าของ wallet + spending cap ก่อนเขียนโค้ดบรรทัดแรก
```

## บทเรียน

รอบนี้ยืนยันซ้ำสิ่งที่เจอบ่อยกับ protocol ใหม่ ๆ: **"ติดตั้งแล้วรันจริง" ให้คำตอบที่บทความให้ไม่ได้** บทความบอกว่า "รองรับหลาย chain" แต่พอรันจริงถึงรู้ว่ามันไม่ได้แปลว่า *chain ไหนก็ได้* — มันแปลว่า "chain ที่มี facilitator ยอมรับ" และ SDK จะปฏิเสธตั้งแต่ boot ไม่ใช่ตอนพยายามจ่ายเงิน

```text
"พร้อม" ของงานแบบนี้ ไม่ได้วัดที่บรรทัดโค้ด
วัดที่นโยบาย   (ใครถือกระเป๋า)
วัดที่การเข้าถึง (facilitator รับเชนไหน)
```

สองอย่างนี้ต้องเช็คก่อนเสมอ ก่อนจะลงแรงเขียน integration จริงกับ protocol ตัวไหนก็ตามที่แตะเงินหรือ key
