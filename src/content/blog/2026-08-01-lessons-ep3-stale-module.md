# Lessons Learned EP.03 — แก้โค้ดแล้ว แต่ระบบยังจำเวอร์ชันเก่า

23 กรกฎาคม เวลา 11:42 น. แก้ `add_clip.py` เพิ่ม hint เสียง "🔊 แตะหน้าจอเพื่อเปิดเสียง" ให้คลิปทุกอันที่สร้างใหม่ ตรวจไฟล์แล้วถูกต้องครบ

วันถัดมา คลิปใหม่ที่เข้ามาผ่าน Telegram กลับเผยแพร่ออกไปโดย**ไม่มี hint นั้นเลย** ทั้งที่คลิปอีก 8 อันที่สร้างผ่านการรันสคริปต์ตรง ๆ มี hint ครบ

## ต้นตอที่แท้จริง

```text
telegram-clip-listener.service   เริ่มทำงาน 2026-07-23 09:51:46
add_clip.py ถูกแก้             2026-07-23 11:42:44   (หลัง service เริ่มไปแล้ว)
clip ใหม่ผ่าน Telegram         2026-07-24 11:37:34   (เกือบ 1 วันให้หลัง)
```

Python (และภาษาตีความส่วนใหญ่) โหลด source เข้าหน่วยความจำแค่ครั้งเดียวตอนเริ่ม process แล้วไม่กลับไปอ่านไฟล์ใหม่อีกเลย service ที่ `import add_clip` ไปตั้งแต่เช้า จะใช้ `CLIP_TEMPLATE` เวอร์ชันเก่าไปตลอดชีวิตของ process นั้น — ไม่มี error ไม่มี warning ไฟล์บนดิสก์กับโค้ดที่รันจริงแยกทางกันเงียบ ๆ

การรันสคริปต์ตรง ๆ ด้วยมือ import ใหม่ทุกครั้งจึงได้ผลลัพธ์ถูกต้อง แต่ path ที่ผ่าน listener service ที่ import ไว้นานแล้วไม่ได้ผล — **สองทางที่ดูเหมือนเรียกโค้ดเดียวกัน แต่จริง ๆ ใช้คนละสำเนาในหน่วยความจำ**

## ทางแก้

```text
systemctl --user restart telegram-clip-listener.service
```

แค่นั้นจริง ๆ — พร้อมตรวจว่าไฟล์ offset (`.telegram_offset`) ยังอยู่ครบ ไม่มีข้อความไหนถูกข้ามหรือส่งซ้ำ

## กฎที่ตั้งไว้ให้ทุกงานถัดไป

หลังแก้ไฟล์ที่ long-running service ตัวไหนก็ตาม import ไว้ ต้อง **ระบุให้ครบทุก service ที่ import ไฟล์นั้น** แล้ว restart ให้หมดก่อนถึงจะรายงานว่า "แก้แล้ว" — restart แค่ trigger path ของตัวเอง (เช่นรันสคริปต์ตรง ๆ ครั้งเดียว) ไม่นับ ถ้ายังมี process อื่นที่ import โมดูลเดียวกันค้างอยู่

การพิสูจน์ที่ถูกต้องคือรันผ่าน path จริงของ service ที่ยังทำงานอยู่ ไม่ใช่รันแบบ manual แล้วสรุปว่าทุกที่ต้องเหมือนกัน

```text
ไฟล์เปลี่ยน   ≠   พฤติกรรม service เปลี่ยน
ต้องมี restart อยู่ตรงกลางเสมอ ถึงจะเชื่อมสองอย่างเข้าด้วยกัน
```
