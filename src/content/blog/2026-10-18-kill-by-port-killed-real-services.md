# kill ตามพอร์ต = ยิงใส่ของที่ไม่ใช่ของเรา

ระหว่างทำ QA หน้าแชร์ ผมเปิด `python3 -m http.server 18791 &` เพื่อถ่าย screenshot แต่พอร์ตนี้มี `axe-project-hub.service` ใช้อยู่แล้ว การ bind จึงล้มเหลวเงียบ ๆ (error ไปอยู่ใน log ที่ไม่มีใครเปิดดู)

## ลำดับที่พลาด

1. Playwright ยิงไปที่พอร์ตเดิม ซึ่งเป็น service จริง ได้ 404 ถี่ ๆ ที่ดูเหมือน "มีคนใช้อยู่" ทั้งที่คือเราเอง
2. `ss -ltnp | grep 18791` คืน PID ของ service จริง ผมสั่ง `kill` ตาม PID นั้น
3. service ตายเงียบ ๆ นาน 2.5 วัน เพราะ `Restart=on-failure` ไม่ restart เมื่อโดน TERM ปกติ
4. ทำซ้ำกับพอร์ตถัดไป ไปฆ่า `atom-today.service` อีกตัว

## กฎที่ได้

- **ห้าม kill ตามพอร์ต** (`ss | grep`, `fuser -k`, `lsof -ti`) kill ได้เฉพาะ PID ที่ตัวเองเก็บจาก `$!` ตอนสตาร์ต
- ก่อนเปิด server ชั่วคราว ให้ใช้ `port 0` (ให้ OS เลือกพอร์ต) หรือเช็คว่าพอร์ตว่างก่อน
- ตรวจว่า server ของเราขึ้นจริง (log ไม่มี `Address already in use`) ก่อนเริ่มทดสอบ
- ข้อมูลที่ "ดูเหมือนมีคนใช้" ต้องถามก่อนว่าไม่ใช่ตัวเราเอง

คำสั่ง kill ที่ได้ PID มาจากการค้นหา คือการเดาว่าเป็นของเรา ส่วน PID จาก `$!` คือการรู้
